# BalancePet 剩余 6 个形象 · 九状态提示词

本文件补齐目前还没有素材的 6 个形象：`mimo`、`mistral`、`opencode`、`perplexity`、`rwkv`、`seedance`。

它取代 `pet-generation-prompts-1.0.0.zh-CN.md` 里那 10 条"小书灵／小方灵／小墨龙"式锚点——那批锚点描述的是**动物与器物吉祥物**，与项目实际交付的 12 套素材（**人类少女 Q 版半身像**）方向相反，按它出图会和已有形象接不上。本文件的锚点全部按参考立绘重写，与已完成的 12 套对齐。

## 1. 先读这一段：风格是怎么统一的

风格统一**不是靠形容词，是靠"逐字不变"**。每张图由三段拼成：

```text
主提示词（第 2 节，54 张图全部逐字相同）
+ 身份锚点（第 3 节，每个角色一句，确定后不再改）
+ 状态动作句（第 4 节，九选一）
+ 该角色自己的参考图
```

只要主提示词标点都不动、参数不改、参考图用对角色的那张，出来的就是一套。

**最容易毁掉一致性的三件事**：中途换模型、中途把 `质量` 从 medium 改成 high、身份锚点写着写着顺手"优化"了措辞。

## 2. 主提示词（复制整段，只替换尖括号里的两处）

```text
为 BalancePet 桌面宠物生成一张独立状态素材 PNG。

角色身份：<身份锚点>
状态动作：<状态动作>

严格以附带参考图为唯一角色身份依据，保留参考图的脸型、发型与发色、瞳色与眼型、服装主色、
材质和核心配饰；不要复制参考图中的文字、Logo、水印、UI、场景、其他角色和医疗设备。
把参考图中的全身立绘转成 Q 版化的人类少女半身胸像。

构图与取景：正方形 1:1，1024x1024，半身胸像（从头顶到腰部或双手），角色充满画布、
上下左右贴边，不留大面积空白；正面或轻微三分之二视角，角色居中对齐；
镜头距离、头顶位置和身体下缘在所有状态之间保持稳定。

画风：清爽的二次元 Q 版角色插画，细线稿，描边为深色偏冷而非纯黑粗线；
柔和渐变叠加轻度赛璐璐上色，头发高光通透，眼睛超大且带一到两层高光与星形反光；
缩小到桌宠尺寸（约 238 像素）后，脸部和核心配饰仍然清楚。

状态表达：只通过表情、眼神、手势和身体重心表达状态；动作幅度小、自然、适合循环播放，
不要用文字或图标代替表演。

背景：纯透明，真正 RGBA Alpha 通道，透明像素必须为 Alpha 0。
严格禁止：白色、灰色、黑色或棋盘格背景（不要把棋盘格画进图里）；场景、地面、投影、
光晕、粒子、速度线、气泡、箭头、表情符号、文字、Logo、水印、UI、边框、九宫格、
分镜、重复角色、额外手臂或腿、裁切脸部、漂浮。

只输出一张透明 PNG，不要附加说明文字，不要把文件名或状态名称画进图片。
```

> 注意：这里的 **1024x1024** 和"半身胸像、贴边"是刻意写死的。`csharp-art-pipeline.md` 早期推荐的是 2048 全身立绘加 8% 安全边距，但实际交付的 12 套全部是 1024 贴边胸像，主程序 `PetImage` 用 `Stretch="Uniform"` 缩放到 238×238 显示，所以按实际交付的画法走才不会接不上。

## 4. 九状态动作句（把句子填进 `<状态动作>`）

| 文件名 | 状态动作 |
| --- | --- |
| `idle.png` | 安静待机，身体只有轻微呼吸、眨眼或材质摆动，眼神自然，肢体放松；不要挥手、奔跑、跳跃或新增道具。 |
| `loading.png` | 专注等待结果，身体略微前倾，眼睛聚焦，核心配件有轻微准备动作；不要画加载图标、旋转符号、进度条或文字。 |
| `success.png` | 任务成功后的轻快开心姿势，露出自然笑容，一只手做小幅庆祝动作；不要画勾号、星星、礼花或漂浮特效。 |
| `error.png` | 遇到错误后的抱歉和困惑表情，眉眼略显沮丧，双手做轻微道歉姿势；不要画红叉、警告符号、烟雾或文字。 |
| `low.png` | 余额偏低时的疲惫、担心状态，肩膀略低，表情克制但可读；不要画数字、硬币、警报或额外道具。 |
| `inactive.png` | 长时间无操作后的安静休息，眼睛闭合或半闭，身体轻微松弛；不要画床、枕头、场景或漂浮的 Z 字。 |
| `clicked.png` | 被点击后的短暂惊讶反应，眼睛稍微睁大，身体轻微弹起或回头；不要添加点击波纹或 UI。 |
| `codex-working.png` | AI 任务进行中，表情专注，身体略微前倾，双手保持工作姿态；不要出现电脑、代码、文字或 UI。 |
| `codex-done.png` | AI 任务完成后的放松和满足，表情温和，姿态恢复稳定，可有轻微点头或抬手；不要画完成图标。 |

## 5. 生成参数（一个都不要改）

| 项 | 值 |
| --- | --- |
| 模型 | `gpt-image-2-official` |
| 提示词 | 主提示词整段 + 该角色的身份锚点 + 一条状态动作句 |
| 参考图 | `素材/二次元形象/<角色>/参考图.png`，文件名一律小写，例如 `rwkv.png`、`gpt-image2.png` |
| 分辨率 | `1k` |
| 宽高比 | `1:1` |
| 输出格式 | `png` |
| 背景 | `transparent` |
| 审核强度 | `auto` |
| 图像数量 | `1` |
| 质量 | `medium` |

## 6. 每个角色的生成顺序

**先生成 `idle.png`，确认身份对了再生成其余 8 个。** 其余 8 个状态要把该角色的 `idle.png` 当参考图附上，而不是继续用原始立绘——原始立绘是全身，反复用它会让取景一路往回漂。

```text
第 1 步  idle.png     参考图 = 该角色的参考立绘
第 2 步  其余 8 个     参考图 = 上一步确认合格的 idle.png
```

建议的推进顺序：

1. `seedance`（参考图本身最接近 Q 版，最容易一次成功）
2. `mimo`（色彩与配饰清晰）
3. `opencode`（黑白灰单色，辨识度高、成本低）
4. `perplexity`（道具偏多，注意只留提灯）
5. `mistral`（层叠裙需要压缩）
6. `rwkv`（文字与翅膀最多，必须彻底清除才适合做亲近感强的桌宠）

## 7. 验收

每个状态出图后逐张检查：

1. 是否 RGBA，透明像素是否真的为 Alpha 0（不是白底、灰底或把棋盘格画进图里）。
2. 是否 1024×1024，头顶位置和身体下缘在所有状态之间是否稳定，没有跳基线。
3. 是否出现文字、Logo、水印、UI、条码、二维码、第二个角色、裁切脸部。
4. 缩小到约 238 像素后，脸部与核心配饰是否仍然认得出。
5. 六个角色的取景是否一致：都是贴边半身胸像，头的大小接近。

可以直接用脚本验收：

```powershell
python tools/prepare-pet-assets.py --check
```
